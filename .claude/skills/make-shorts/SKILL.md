# 朗読ショートを作る

手順の詳細と根拠は `docs/runbook.md`。ここは Claude が実行するときの段取り。
作業のルートは `D:\prj\ai-shorts`、Python は `.venv\Scripts\python`（以下 `py`）。

## 段取り

1. **計画を立てる**：何本・どんなジャンルか、既存の物語を使うか新しく書くかを依頼から決める。曖昧なら本数とジャンルの希望だけ聞く。
2. **エンジンを確かめる**：`py scripts/tts_status.py`。止まっていれば起動する（runbook 2）。セッションをまたぐと止まっているのが普通。
3. **物語**：新しく書くなら write-stories スキルに従って下書き → 検査 → **ユーザーの承認を待つ**。承認前に背景や合成へ進まない（承認されなければ無駄になるうえ、決まり 6 に反する）。
4. **背景**：pick-backgrounds スキルに従って、段落ごとに1枚を ID で取る。候補シートは自分で見て選び、外れ（広告・ロゴ・雰囲気違い）は除く。
5. **合成**：`py -m ai_shorts all --id <id>`（複数なら id ごと）。止まったらエラーの文面どおりに直す（多いのは「長すぎる」→ 本文を短くしてユーザーに確認、「接続できない」→ エンジン起動）。
6. **確認**：qa が全部 OK か見る。`py scripts/preview_video.py <id>` のコマ画像を自分で見て、字幕・背景・クレジットの崩れがないか確かめる。数字の検査だけで終わらせない（QA は見た目の違和感までは拾えない）。
7. **渡す**：`ready/<id>.mp4` をユーザーに送り（SendUserFile）、表で「タイトル・長さ・声」をまとめる。説明文は `ready/<id>.txt`。
8. **残っていることを伝える**：BGM なし・スマホでの見た目は未確認、など。投稿はユーザーが YouTube Studio で手動（自動投稿は作らない）。

## 守ること（理由つき）

- **承認はユーザーだけ**：`scripts/approve_story.py` はユーザーが「承認」と言ったときにだけ実行する。生成物を自分で承認しない。
- **59 秒以下**：Content ID の申し立てが付いた1分超のショートはブロックされる。qa の「長さ」が NG なら出さない。
- **ダウンロードは了承を得てから**：エンジン・声の追加は数百 MB〜1GB 超。何を・どこから・何 MB かを伝えてから。
- **有料 API・自動投稿は使わない**（CLAUDE.md）。
- **方針に関わる判断**（新しい声、新しい画像の出どころ、字数の目安の変更など）は `docs/decisions.md` に追記する。

## 渡すときの書き方（例）

| ファイル | タイトル | 長さ | 声 |
|---|---|---|---|
| ready/20261120-001.mp4 | 〇〇 | 48.2秒 | COEIROINK:おふとんP |

そのあとに「まだのこと」（BGM、スマホ確認など）を短く。
