# BGM のルール

## TuneCore Japan の Content ID に登録できない曲

TuneCore Japan のヘルプ「【YouTube コンテンツ収益化サービス】登録できない楽曲は？」より（要点）：

- フリー素材などの音源を含む曲（GarageBand のループ音源素材、効果音素材、**生成AI楽曲**など）
- 第三者が権利を持つ音源を含む曲（サンプリング音源、ライセンス音源）
- オリジナル曲のカラオケ、アカペラ、インスト、**ショート**、リマスター、ライブ版
- カバー曲、パブリックドメインの曲
- ゲームのサウンドトラック

申請前に必ず最新の規約を確認すること。

## 作り方の方針

| 役割 | 担当 |
|---|---|
| メロディ・和音・構成（作曲） | **ユーザー**。REAPER のピアノロールで打ち込み、MIDI で書き出す |
| 音色（シンセエンジン）・レンダリング | Claude と一緒に numpy で作る |
| 生演奏（ギターなど） | ユーザー。最も確実に「人の作品」として扱われる |

- Claude にメロディや和音を考えさせない（生成AI楽曲扱いを避ける）。
- MIDI を SoundFont で鳴らさない。numpy のシンセで WAV に直接書き出す。
- 作曲の証拠を残す：REAPER のプロジェクトファイル、日付つきの MIDI、git の履歴。

## 曲の仕様

- 長さ **2:00〜3:00**。A→B→A など展開をつける（単純なループにしない）。
- **冒頭 0:00〜0:60 だけでも1曲として成立する**ように作る（ショートで使う部分）。
- 配信するのは完全版だけ。60秒版を別の曲としてリリースしない（「ショート」版は登録対象外）。
- 書き出し：WAV 44.1kHz / 16bit 以上、−14 LUFS 前後。
- ジャケット画像も自作する。

## ショートへの BGM の付け方（2026-11-20 調べ）

付け方は2つある。どちらにするかは、下の検証で決める（decisions.md の「未決定」）。

| | 焼き込み（いまのパイプライン） | アプリで「サウンド」として付ける |
|---|---|---|
| やり方 | render で mp4 に BGM を混ぜる | BGM なしの mp4 を、スマホの YouTube アプリで上げるときに曲を選ぶ |
| 投稿 | `upload`（API）でも Studio でもよい | アプリからだけ。API・パソコンの Studio では付けられない |
| 曲の認識 | Content ID が音から検出して申し立てる | 曲として紐づく（曲名が出る） |

- **API ではサウンドを付けられない。** YouTube Data API の videos リソースに、音源ライブラリの曲を紐づける項目はない。
- **投稿後には付けられない。** 公式ヘルプにあるのはアプリでの手順（撮影前の「サウンドを追加」、撮影後の「サウンド」）だけ。Studio のエディタで後から付けられるのは、YouTube オーディオライブラリ（無料の曲）だけ、という説明が多い。
- **収益の分け方。** ショートの収益分配では、「音楽」を「音楽パートナーが提供した、または Content ID で申し立てたコンテンツ」と定義している。曲が1つなら、そのショートの収益の半分が音楽ライセンスの分に回る（曲の数で分ける）。焼き込んで検出されただけの曲も数える、とはっきり書いた一文は見つかっていない。
- **自分の曲がアプリの音源ライブラリに出る条件。** 曲を提供したパートナーが、YouTube とショート用の契約を結んでいること。TuneCore Japan が対象かは未確認。
- **アプリで付けたときだけ得られそうなこと。** 曲名の表示、曲のページの「このサウンドを使ったショート」への掲載、ほかの人がその曲を使えるようになること。焼き込みでも同じになるかは分かっていない。
- 出典：[Shorts の収益化ポリシー](https://support.google.com/youtube/answer/12504220)、[ショートで使える音楽](https://support.google.com/youtube/answer/13486873)、[ショートの編集](https://support.google.com/youtube/answer/16215842)、[videos リソース](https://developers.google.com/youtube/v3/docs/videos)

## 申請と検証の手順

1. 特徴のはっきりした1曲を選び、TuneCore Japan で配信と Content ID を申請する。
   - 配信先を個別に選べるプラン（体験談ではスタンダード以上）か、Pay Per Release かを料金で比べて決める。
   - 自分のチャンネルを除外リストに入れない。
   - ショートの音源ライブラリに曲が出るか（YouTube とショート用の契約があるか）を TuneCore Japan に確かめる。
2. 審査の結果を docs/decisions.md に記録する。断られたら理由を記録し、作り方を見直す。
3. 通ったら、BGM の音量を −14 / −18 / −22 dB にした3本を限定公開で上げ、申し立てが付く音量の下限を確認する。結果を `bgm_gain_db` の初期値にする。
   - 申し立ては、アップロードした時点で Content ID が調べる（公開しなくてよい）。Studio の「コンテンツ」→「ショート」→「制限」の列で、曲名・申し立て者・対応（収益化／ブロック／追跡）を見る（手順は runbook.md 3-6）。API からは読めない。
   - 結果が出るまでの時間は決まっていない。翌日にもう一度見て、遅れて付くものがないか確かめる。
   - あわせて、焼き込んだショートに曲名が出るか、曲のページに並ぶかを見る。
   - 曲がアプリの音源ライブラリに出ていれば、BGM なしの版をアプリで上げてサウンドとして付けた1本も作り、見え方を比べる。
4. 数本投稿して、TuneCore 側に収益が計上されるかを確認する。焼き込みでも計上されるなら、投稿は `upload`（API）のままにする。計上されないなら、アプリで付ける流れに変える（render に BGM なしの版を出す設定を足す）。結果は decisions.md に記録する。
