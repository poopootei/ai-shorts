# 動画づくりにかかるトークンと時間（2026-11-21 の計測）

物語を書いてから動画CHECK に出すまでに、Claude Code のトークンと時間がどれだけかかっているかの記録と、改善の候補。
すぐには直さない。直すときはこの表から選び、決めたことは decisions.md に書く。

## 計り方

- 対象：仕組みを作ったセッション（2026-11-20〜21、API 呼び出し 136 回）の transcript。
- 「実効トークン」= 入力 ×1 ＋ キャッシュ書き込み ×2 ＋ キャッシュ読み込み ×0.1 ＋ 出力 ×5（料金の重みに近づけた目安）。
- 工程の時間は `work/{id}/` のファイルの更新時刻から読んだ。

## 結果

### 1回の依頼（バッチ）あたり

| バッチ | 依頼 | 実効トークン | Claude の作業時間 | できたもの |
|---|---|---|---|---|
| A（11/20） | 物語3本 → 承認 → 背景・合成 | 約 80 万 | 約 10 分 | 動画3本（あとで字幕の直しに +43 万） |
| B（11/21） | 物語3本 → 承認2本 → 背景・合成 | 約 136 万 | 約 8 分 | 動画2本（OK は1本） |

- 動画1本あたり 約 27 万（A）〜 68 万（B）。B が高いのは、会話が長くなって1回の呼び出しが重くなったため（下）。
- 人の待ち時間（物語CHECK・動画CHECK）は含まない。

### お金がかかっている場所

| 種類 | 割合 | 中身 |
|---|---|---|
| 会話の読み返し | 64% | 呼び出しのたびに、それまでの会話全部（平均 20 万トークン）を読み直す |
| 新しく増えた分 | 22% | コマンドの出力、画像、読み込んだスキルや文書 |
| Claude の出力 | 14% | 物語の本文、考える過程、返事の文章 |

- 呼び出し1回の重さは、会話の長さで決まる。最初は 約 7 万トークン（指示とツールの説明だけ）、終わりごろは 約 30 万。**同じ作業でも、長い会話の終わりでやると 3〜4 倍高い。**

| 作業（呼び出しの中身） | 割合 |
|---|---|
| パイプラインのコマンド（検査・背景・合成・状態の記録） | 31% |
| git（コミット・マージ・rebase）とその他のコマンド | 17% |
| 文章だけの返事 | 12% |
| スキルの読み込み | 12% |
| ファイルを書く（物語の JSON など） | 8% |
| 画像を見る（候補シート・コマ画像、12回） | 8% |
| そのほか（送る・まとめ・編集） | 12% |

## 改善の候補（トークンを中心に）

効果の大きい順。★ = 効果、☆ = 手間。

| # | やること | 効果 | 手間 | 理由 |
|---|---|---|---|---|
| 1 | **1回の依頼ごとに新しいセッションで始める**（作業が終わったら区切る） | ★★★ | ☆ | 読み返しが64%。会話が短いうちは1回の呼び出しが 1/3〜1/4 で済む。記録はファイル（status・history）にあるので、引き継ぎは要らない |
| 2 | **本体（D:\prj\ai-shorts）で直接作業する**（物語・動画づくりは worktree を使わない） | ★★ | ☆ | worktree からは本体に書けないため、毎回「コミット → マージ（→ rebase）」が要り、呼び出しが 5〜8 回増えていた。コードを変えるときだけ worktree にする |
| 3 | **背景の候補を1枚のシートにまとめる**（全物語・検索語を多めに一度に出し、縮小して1回で見る） | ★★ | ☆☆ | 画像1枚ごとに会話が増え、以降の呼び出しでずっと読み返される。1物語あたり 2〜3 回のやり直しも減らせる |
| 4 | **検査の出力を短くする**（check_story の読みは、怪しい語だけ出す。AivisSpeech の読みとアクセントも同じコマンドで出す） | ★★ | ☆☆ | いまは全文の読みを出していて、1本あたり数千トークンが会話に残る。AivisSpeech は別のスクリプトを書いて確かめていた |
| 5 | **背景〜合成〜コマ画像を1つのコマンドにする**（`ai_shorts make --id A --id B`） | ★ | ☆☆ | コマンドの往復（呼び出し）が減る。複数の物語をまとめて流せる |
| 6 | **スキルを短くする**（よく使う手順だけを残し、細かい根拠は docs に任せる） | ★ | ☆ | スキルは読み込むたびに会話に残る。1回のバッチで 3〜5 個読んでいた |
| 7 | **返事を短くする**（表と要点だけ。全文の物語は物語CHECK のときだけ） | ★ | ☆ | 出力は重みが大きい（×5） |
| 8 | **背景写真を探すのをやめ、画像生成（ComfyUI）に切り替える** | ★★（時間も） | ☆☆☆ | 合う写真がなく検索のやり直しが多い。同じ被写体を続けて出せない（雪だるまのボツ） |

### 時間の改善

- いちばん長いのは背景探し（やり直し込みで 1本 1〜2 分）。3・8 で短くなる。
- 合成は 1本 1 分弱で、いまは十分速い。本数が増えたら、複数本を並べて動かす（5）。
- 人の CHECK の待ちは、ここでは減らさない（決まり 6・D-012）。
