## D-015 2026-11-20 YouTube への投稿を API の予約投稿にする（D-003 の見直し）
- 2026-11-02 から、審査を通っていない API プロジェクトから上げた動画も、非公開に固定されなくなった（YouTube Data API の改訂履歴と videos.insert の説明で確認）。D-003 の理由がなくなったので、ユーザーが自動化に決めた。

- 人の確認は減らさない。物語CHECK・動画CHECK はそのまま（物語CHECK は D-018 でやめ、動画CHECK だけにした）。`upload` を実行するのはユーザーが「投稿して」と言ったときだけで、Claude はまず `--dry-run` で公開の予定を見せて了承を得る。定期実行で勝手に投稿する仕組みは作らない。
- API は YouTube Data API v3（無料。アップロードは 1 日 100 回の枠）。権限は `youtube.upload` だけ。認証情報は `secrets/`（git 管理外）。依存に google-api-python-client と google-auth-oauthlib を足した（ユーザーが了承）。

- 「改変または合成されたコンテンツ」の申告（`containsSyntheticMedia`）は false。合成音声で朗読しているが、実在の人や出来事に見えるものではないため。変えるなら `youtube.contains_synthetic_media`。
- YouTube Studio から手で上げることもできる。そのときは従来どおり `posted` で記録する。

## D-016 2026-11-21 タブレットから上げるために、投稿待ちを MiniPC で受け渡す
- ユーザーがタブレットの YouTube アプリから手で上げたいので、`upload/` の動画とタイトル・説明文・タグを LAN の MiniPC（`lenovo`、Ubuntu）に置き、タブレットのブラウザで動画を保存し、文をコピーできるようにした。Google ドライブは使わない（このPCにドライブのアプリがなく、API を足すと権限が増えるため）。
- `python -m ai_shorts share` で送る。送るのは ssh だけ（`~/.ssh/config` の Host 名、`share.host`）。同じ大きさの動画は送り直さず、`upload/` にないもの（投稿済み・ボツ）は MiniPC から消す。
- MiniPC の Web アプリ（`share_app/server.py`）は Python の標準ライブラリだけで書き、MiniPC に何も入れない。ほかのアプリと同じく `~/projects/ai-shorts-share` に置き、`systemd --user`（`ai-shorts-share.service`）でポート 8040 に出す。LAN 専用で、ログインはない。
- タブレットで「投稿した」（公開日・URL）か「ボツ」（理由・改善案・作り直すか物語ごとか）を送ると MiniPC に印が残り、次の `share` がこのPCの記録（`posted` / `reject-video` と同じ）にして、MiniPC から消す。判断して入力するのはユーザーなので、人が決める方針と合う。`share` までは取り消せる。
  - ボツで改善案が空のものは記録しない。`share` が「要対応」と出すので、Claude が改善案を出してユーザーに確かめ、`reject-video` で記録する（ボツの理由と改善案を必ず残す決まりのため）。
- 投稿するかどうかは人が決めるまま（CLAUDE.md の2）。`share` は外部（YouTube）に何も送らない。

## D-023 2026-11-23 BGM の音量は「声より何 LU 小さいか」で決める（bgm.below_voice_lu）
- ユーザーの曲（`assets/bgm/track_20261123.wav`、72秒、−14.5 LUFS）を「物語で学ぶ日本語」に入れた。
- 音量は、曲の元の大きさに左右されないように、声との差で決める。まず **声より 12 LU 小さく**：声が聞き取りやすく、曲もはっきり聞こえる大きさ。仕上がりでは、BGM だけの冒頭が約 −28 LUFS、全体が −14 LUFS。
- Content ID が認識する下限はまだ確かめていない。bgm.md の検出テスト（3つの音量で限定公開）を、`below_voice_lu` を 10 / 12 / 15 にして行い、結果で見直す。
- 動画の終わりの 1.5 秒で BGM を消していく（`bgm.fade_out_seconds`）。`below_voice_lu` がないチャンネルは、今までどおり `gain_db` を使う。
- 曲の仕様（bgm.md）：Content ID に登録するのは 2〜3 分の完全版。60秒前後の短い版は登録の対象外なので、この72秒のファイルをそのまま申請しない。

- 1字ごとの時刻：timing.json は文の始まりと終わりしか持たないので、`karaoke.py` が voice.wav から話し始め・話し終わりと文の中の間（0.15 秒以上の無音）を探し、読点と対応させる。間と間のあいだは、字の重み（かな1、漢字1.8、小さいかな・記号0）で割る。エンジンの読みは使わない（tts を作り直さずに済み、3D の版のコマもそのまま使える）。漢字の読みの長さは平均で見積もるので、句の中では少しずれることがある。
- 行の切り替えも読みに合わせる（次の行は、読み始める 0.1 秒前に出す）。
- 学習者向け（subs.mode: learner）とレッスン形式（nihongo）は対象外。

## D-031 2026-11-25 3D の人形を自前で作る（老若男女の4体。Blender のスクリプトで生成）
- ユーザー：「フリーのモデルではインパクトに欠ける。老若男女くらいの自分のモデルを持ち、主要な動作もテンプレートにして、手戻りを少なく」「Blender で独自のモデルを作りたい」。
- 作り方：`scripts/blender/make_characters.py` が Blender の中で4体を作り、`assets/3d/characters/own_*.glb` に書き出す。手で直さず、数値（SPECS）を直して作り直す。
  - 形はメタボール（球・楕円体を溶け合わせる）。長さの単位は頭の高さ（hh）で、約5.3頭身の丸い絵柄。髪は大きな楕円体から顔の部分をマイナスのメタボールでくり抜く。外部の素材・画像・生成 AI は使わないので、ライセンスの心配がなく、クレジットも要らない（SOURCES.md）。
  - 服は体の面を高さと位置で色分けし（skin / top / inner / bottom / shoes）、袖口・すそ・えり・カーディガンの縁・ボタン・フード・スカートを部品で足す。スカートの重みは腰から下へだんだん左右のももに移す（座ると前が太ももについていく）。
  - 4体：若い男（パーカー・ジーンズ・白いスニーカー）、若い女（ブラウス・ひざ丈のスカート・ボブ・ほお紅）、年配の男（カーディガン・はげ頭・眼鏡・口ひげ・おなか）、年配の女（カーディガン・白髪のおだんご・眼鏡）。
- 骨は Mixamo と同じ名前・T ポーズ（kit の `RIGS["own"]`）。重みは Blender の自動の重み。Mixamo の動き（`play` / `bake`）も同じ名前のまま移せる。
  - IK の pole は4体とも数値で確かめた：ひざは -π/2（前へ）、ひじは左 π・右 0（後ろ・外・下へ）。
- 表情は形状キー：blink / smile / open / surprise / angry / sad。kit の `expr`（表情を変える）・`blinks`（ときどきまばたき）・`talk`（セリフの口パク）で付ける。
  - glb を読み込むと形状キーがすべて 1 になる（全部の表情が重なる）ので、kit が読み込んだときに 0 に戻す。
- 顔の型（2026-11-25 追記）：「パッと見てキャッチーなものを」（ユーザー）。5つ作って見比べ、ユーザーが E（点目）を選んだ。
  - 型は `FACES`：A 黒目だけ、B キラキラ（大きな黒目・光2つ・上まぶたの線）、C 白目と黒目、D 白目とまぶた（ジト目ぎみ）、E 点目（小さな点の目・太いまゆ・大きな笑い口・全員にほお紅）。まゆ・口・ほお紅の大きさは型ごとの倍率で変える。
  - 見比べ：`make_characters.py -- --out <フォルダ> --compare dot,googly --preview <フォルダ>` で、型ごとの glb と並べた絵（heads_* = 顔の拡大、compare_* = ふだん・笑顔）を書く。書き出す人形の型は BASE の `face`（今は dot）。
  - 点目は口の笑いのカーブが強いので、angry / sad の形状キーはそのカーブを打ち消してから口を下げる。
- 使い方：`kit.person("young_man")`。服の色は `colors={"top": …}` で物語ごとに変えられる（材質の名前で `recolor`）。下見の舞台 `scripts/blender/people_check.py`（座る・立つ・手を伸ばす・歩く・表情・Mixamo の動き。ひじ・ひざの向きも数値で出す）。
- 説明文のクレジット：自前の人形だけなら `blender.credit`（「3D（Blender）」）、舞台が Quaternius の人形を使っていれば `blender.credit_quaternius`（「人形：Quaternius（CC0）」）を `--adopt` で書く。
- Quaternius の2体（casual_man / casual_woman）と、それを使った4本の舞台はそのまま残す。
- 標準にする（2026-11-26 追記）：「デフォルトでこの 3D モデルを使うように」（ユーザー）。これからの舞台は自前の人形で作る。
  - kit の `Character` は rig を省くと `own`、height を省くと `PEOPLE` の身長（file を省くと若い男）。ふつうは `kit.person`。
  - config のクレジットは、`blender.credit` を自前の人形の表記にし、Quaternius の表記は `blender.credit_quaternius` に移した（前は `credit` が Quaternius、`credit_own` が自前）。
  - Quaternius で作った4本は動画CHECK を通って `upload/` にあるので、作り直さない。
- 残り：主な動きのテンプレート（うなずく・驚く・指さす・頭をかかえる など、人形を問わず「誰が・いつ・どの動き」で呼べる形）と、使い回せる舞台の部品。見た目はユーザーがスマホで見て決める（下見の絵を見てもらう）。
