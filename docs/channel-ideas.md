# 新しいチャンネルの案

2つ目以降のチャンネルの候補。どれを始めるかは未決定（decisions.md の「未決定」）。始めると決めたら、そのチャンネルの channel.md を作り、ここから移す。
扱う場所はこのリポジトリ（D-015）、アニメーションは Remotion で試作する（D-016）。

## 進め方の方針（2026-11-21）

- **まずはショート（59秒以下）だけで攻める。** 長尺（朗読まとめなど）は、チャンネルに人気が出てから考える。
- AI で作るチャンネルが続くかどうかは、**人が足しているもの**がはっきりしているかで決まりやすい。どの案も「何を人が足すのか」を決めてから始める。
- YouTube は、同じ型で大量に作った動画を「inauthentic content」（2025年7月に repetitious content から改名）として収益化の対象から外す。テンプレートで数字や単語だけを替える作り方は避ける。

## 案1：数秘術 ＋ 物語

### 中身
- その日・その月のナンバー（日付の数字を足して1桁にしたもの）をテーマに、毎日1本。例：2026-11-21 → 2+0+2+6+1+1+2+1 = 15 → 1+5 = **6の日**。
- 「今日は6の日。6は『世話焼き』の数字」と紹介したあと、その数字の性質を持つ人物の30秒ほどのショートショートにつなげる。
- 日替わりとは別に、日付に縛られない「誕生数3の人の取扱説明書」のようなシリーズも混ぜる。

### いいところ
- 日付と数字の組み合わせで、ネタが尽きない。予約投稿と相性がよい。
- 素材は数字の文字アニメで済む。Remotion がいちばん得意な種類の動画。
- 落ち着いた BGM が前に出るので、Content ID の考え方（D-001）に合う。
- 物語を付けることで、数秘術だけの動画と差がつく。今のチャンネルの物語づくり（write-stories、story-guidelines.md）がそのまま使える。人が足すものは「物語を選んで直すこと」になり、上のポリシーの心配も薄くなる。

### 懸念点
- **日付つきの動画は翌日には古くなる。** 長く再生され続けるのは、日付に縛られないシリーズのほう。両方の割合を決める。
- **占い系のショートは競合が多い。** 物語を付けても埋もれないか、試作で確かめる。
- **数字の意味がぶれないようにする。** 1〜9 とマスターナンバー（11・22・33）の意味の一覧と、計算の規則（マスターナンバーを1桁にまとめるかどうか）を先に決めて、ファイルに固定する。
- **占いであることを明記する。** 断定や、健康・お金について不安をあおる言い方はしない。説明文に「エンターテインメントとして」と書く。
- 物語は 30 秒ほどに短くなるので、250〜280字の指針（D-006）とは別の字数の目安が要る。

### 次に決めること
- 数字の意味の一覧と計算の規則
- 1本の構成（紹介と物語の秒数の配分）
- 日替わりと、日付に縛られないシリーズの割合

## 案2：コント ＋ サラリーマンあるある

### 中身
- 2人のキャラクターが掛け合う 30〜45 秒のアニメーションのコント。「Fラン大学就職チャンネル」「コンサルのリアル」のような職場ものの、ショート版。
- テーマはサラリーマンのあるある。型（「建前と本音」「面接官の心の声」「業界用語の翻訳」「新人とベテランのずれ」など）× 場面 × オチ で台本を作る。
- **ネタは Twitter（X）から拾う。** よく話題になっている「あるある」を集め、それをもとに自分たちで台本を書く。

### いいところ
- あるあるは共感されやすく、コメント欄が盛り上がる。チャンネルが育てば、コメントそのものがネタの源になる。
- 型があるので、Claude が下書きを20本出し、人が3本選ぶ流れが作れる。
- 2人の声は、今の音声合成（COEIROINK・AivisSpeech）で足りる。口パクは、モーラごとの長さか wav の音量から作れる（D-016）。

### 懸念点
- **Twitter のネタは、そのまま使わない。** 投稿の文章や、特定の人のオチをまねると、盗用や著作権の問題になる。拾うのは「よくあるテーマ」までにして、台本は自分たちで書く。特定の人の体験談を使うなら、本人の了承を取る。
- **Twitter からの集め方。** X の API は有料で（CLAUDE.md の1）、自動で集めるのは規約で禁止されている。人が見て、気になったものを手でメモする。
- **職場ものの枠はすでに混んでいる。** 業界や視点を絞って差をつける。候補：「上司がAIにハマった職場」「AI導入を任された現場」など、自分の経験が使える分野。
- **素材のライセンス。**
  - いらすとや：商用利用は1つの制作物につき20点まで無料（だったはず。使う前に最新の規約で確かめる）。使っているチャンネルが多く、見た目で覚えてもらいにくい。
  - 「アニメ素材」：何を使うかで、ライセンスの確認が別に要る。
  - SVG のコードで描く自分のキャラクターなら、ライセンスの心配がなく、チャンネルの顔として覚えてもらえる（D-016）。
- 実在の会社名・人名は出さない。特定の職業を見下す笑いにしない。
- 台本の形式（話者・セリフ・表情・間）と書き方の指針がまだない。

### 次に決めること
- 絞る業界・視点
- キャラクターの見た目（SVG で描くか、素材を使うか）
- 台本の形式と、ネタのメモの置き場

## 案3：青空文庫の紹介

### 中身
- 青空文庫にある、著作権の切れた作品を1分で紹介する。あらすじ、作品の一節の朗読、読みどころ。
- 作家の候補：夢野久作、小川未明、新美南吉、芥川龍之介、宮沢賢治など。とても短い掌編なら、まるごと朗読もできる。

### いいところ
- 人が書いた名作なので、AI 量産の心配がない。人が足すものは「作品を選ぶ目」と「読みどころの紹介」。
- 今の仕組み（朗読・字幕・背景・BGM）がほぼそのまま使える。
- 作品の数が多く、ネタが尽きない。

### 懸念点
- **著作権の切れていない作品も、青空文庫にはある。** 作者の許可を得て公開している作品は、商用利用できないことがある。日本では、1967年以前に亡くなった作家の作品は著作権が切れている（1968年以降に亡くなった作家は、死後70年まで保護される）。作品ごとに確かめる。
- **翻訳ものは、訳者の著作権が残っていることがある。** 原作者ではなく、訳者の没年で確かめる。
- 青空文庫のファイルの取り扱い規準を確かめ、底本と入力・校正した人の情報の載せ方を決める。
- 旧字・旧仮名や古い言い回しを、音声合成が読み間違えやすい。読みの直し（fix-readings）の手間が増える。
- 古典は冒頭の「つかみ」が弱くなりやすい。hook の作り方を工夫する。
- 1分に収まる作品は限られる。抜粋するなら、区切り方が大事。

### 次に決めること
- 紹介が中心か、朗読が中心か
- 作品を選ぶ基準と、著作権を確かめる手順
